หัวข้อ 5 · 16 นาที

ประเภทของข้อมูล และข้อควรระวังเรื่อง PDPA

นึกภาพก่อน

ธนาคารแห่งหนึ่งมีตารางยอดโอนเงิน รูปถ่ายใบหน้าลูกค้า และไฟล์เสียงจาก Call Center ทั้งสามอย่างเป็น "ข้อมูล" แต่วิเคราะห์ด้วยวิธีเดียวกันไม่ได้ ก่อนวิเคราะห์จึงต้องตอบให้ได้ก่อนว่าข้อมูลตรงหน้าเป็นประเภทใด

ทำไมต้องรู้จักประเภทของข้อมูลก่อน

  • เพื่อ แยกแยะ ข้อมูลประเภทต่าง ๆ ได้
  • การแบ่งมีหลายแบบ: ตาม โครงสร้าง (Structure), ตาม ความเป็นเจ้าของ (Data Owner) และตาม คุณลักษณะทางสถิติ
  • การวิเคราะห์ข้อมูลเกี่ยวข้องกับสถิติพื้นฐาน เมื่อแยกประเภทได้จึง เลือกวิธีทางสถิติที่เหมาะสม ได้

แบ่งตามโครงสร้าง

Structured DataUnstructured Data
การแสดงผลแสดงเป็น rows, columns และ relational database ได้แสดงเป็น rows, columns ไม่ได้
ตัวอย่างตัวเลข วันที่ ข้อความ (numbers, dates, strings)รูปภาพ เสียง วิดีโอ ไฟล์เอกสาร อีเมล
สัดส่วนในองค์กร (Gartner)ประมาณ 20%ประมาณ 80%
พื้นที่จัดเก็บใช้ น้อยกว่าใช้ มากกว่า
การจัดการและป้องกันง่ายกว่า ด้วยเครื่องมือเดิมยากกว่า

หมายเหตุจากเอกสาร

ตารางเปรียบเทียบในสไลด์ (อ้าง Gartner) ใส่ "spreadsheets" ไว้ฝั่ง Unstructured ร่วมกับ word processing files และ e-mail แต่แบบทดสอบในสไลด์เดียวกันจัดข้อมูลที่อยู่ในตาราง (ยอดเงินโอน, จำนวนสินค้าที่ขายได้, สินค้าคงคลังใน Database) เป็น Structured ทั้งหมด ข้อสอบในเว็บนี้ยึดตามแบบทดสอบ: ข้อมูลที่จัดเป็นแถวและคอลัมน์ได้คือ Structured

แบ่งตามความเป็นเจ้าของ (Data Owner)

ประเภทที่มาตัวอย่างในสไลด์
1st Party Dataบริษัทเก็บเองโดยตรงจากลูกค้าของตัวเองข้อมูลฝากถอนเงินของลูกค้า, ข้อมูลสมัคร Member, Transactions ที่ลูกค้าซื้อสินค้า
2nd Party Dataข้อมูลของบริษัท Partner ที่แบ่งปันกันข้อมูลจาก Platform ส่งของ (Delivery) ที่เป็น Partner, ข้อมูลผู้ให้บริการมือถือที่เป็น Partner
3rd Party Dataข้อมูลที่รวบรวมจากคนจำนวนมากโดยผู้อื่นข้อมูล Social Media ทั่วไป

เปรียบเทียบ คุณภาพ (Quality) กับ การเข้าถึงผู้คน (Reach):

QualityReach
1st Partyสูงสุดต่ำสุด
2nd Partyกลางกลาง
3rd Partyต่ำสุดสูงสุด

ยิ่งเป็นข้อมูลของเราเอง ยิ่งแม่นแต่ครอบคลุมคนได้น้อย ยิ่งเป็นข้อมูลจากภายนอก ยิ่งครอบคลุมคนมากแต่คุณภาพลดลง

แบ่งตามวิธีการทางสถิติ

กลุ่มใหญ่กลุ่มย่อยตัวอย่างในสไลด์
Numerical Data (Quantitative)Discrete Data (นับเป็นจำนวนเต็ม)จำนวนลูกค้า, จำนวนสินค้า
Continuous Data (ค่าต่อเนื่อง)ยอดขาย, ภาษีมูลค่าเพิ่ม
Categorical Data (Qualitative)Nominal Data (ไม่มีลำดับ)เพศ, สัญชาติ
Ordinal Data (มีลำดับ)คะแนนความพึงพอใจที่สำรวจจากลูกค้า

จากแบบทดสอบในสไลด์:

  • คอลัมน์ Age → Numerical · คอลัมน์ Occupation → Categorical
  • คอลัมน์ Branch → Categorical · คอลัมน์ Gross income → Numerical

ตัวอย่างข้อมูลในธุรกิจ

ชนิดคอลัมน์ตัวอย่าง
Transactional DataSales Transaction, Products, Category, Order ID, Customer ID
Customer DataName, E-mail, Age, Gender, Income, Occupation, Address, Customer ID
Payment DataPaid Date, Paid Amount, Payment ID, Customer ID
Campaign DataCampaign Code, Campaign Response, Customer ID

แบบทดสอบในสไลด์: ดูตารางแล้วบอกชนิด

ตารางมีคอลัมน์ชนิด
Customer ID, Age, Education, Marital status, Occupation, Race, Sex, Native-country, SalaryDemographic Data (ลักษณะของตัวบุคคล)
Account No, DATE, TRANSACTION DETAILS, WITHDRAWAL AMT, DEPOSIT AMT, BALANCE AMTTransactional Data (รายการที่เกิดขึ้นแต่ละครั้ง)
Invoice ID, Branch, Customer type, Product, Unit price, Quantity, Total, PaymentInvoice Data
CATEGORY_NAME, PRODUCT_NAME, LIST_PRICE, WAREHOUSE, QUANTITYInventory Data (สินค้าคงคลัง)

วิธีแยก: Demographic บอกว่า "คนนี้เป็นใคร" ส่วน Transactional บอกว่า "เกิดอะไรขึ้น เมื่อไร เท่าไร"

ทุกตารางมี Customer ID ร่วมกัน จึงเชื่อมข้อมูลข้ามตารางได้ การจัดเก็บใน Database แสดงความสัมพันธ์ด้วย ER Diagram (ER ย่อจาก Entity Relationship)

นำข้อมูลไปใช้ประโยชน์

  • สร้าง Report หรือ Dashboard เพื่อติดตาม KPI (Key Performance Index) เช่น ยอดขาย กำไร สินค้าคงคลัง สินค้าระหว่างจัดส่ง
  • วิเคราะห์สถานะธุรกิจ: สินค้าใดขายดี สาขาไหนยอดขายดีที่สุด แต่ละช่วงเวลายอดขายต่างกันหรือไม่
  • สร้าง AI หรือ Machine Learning เพื่อทำนาย เช่น ลูกค้าคนใดจะ Churn, ใครจะตอบรับแคมเปญ, แต่ละคนจะสร้างรายได้เท่าไร (CLTV)

ข้อมูลส่วนบุคคลและ PDPA

หลักการเก็บข้อมูลส่วนบุคคล 5 ข้อ:

  1. ห้ามเก็บโดย ไม่ได้รับความยินยอม (ต้องขอ Consent)
  2. ห้ามเก็บ เกินความจำเป็น
  3. ต้อง บอกวัตถุประสงค์ ในการเก็บ
  4. หาก เปลี่ยนวัตถุประสงค์ ต้องแจ้งเจ้าของข้อมูลให้ทราบ
  5. ห้ามเก็บจากแหล่งอื่น ต้อง เก็บโดยตรงจากเจ้าของข้อมูล

เพื่อลดโอกาสที่ข้อมูลส่วนบุคคลรั่วไหล บริษัทจะสร้าง Customer ID ไว้อ้างอิงภายใน ผู้ที่ไม่เกี่ยวข้องจึงไม่เห็นข้อมูลส่วนบุคคลของลูกค้า

ตัวอย่างไล่ทีละขั้น

วิดีโอ CCTV ที่ใช้นับลูกค้าเข้าออกร้านUnstructuredเป็นวิดีโอ จัดเป็นแถวและคอลัมน์ไม่ได้
สินค้าคงคลังที่เก็บใน Database (DBMS)Structuredอยู่ในตารางของ database
จำนวนสินค้าที่ขายได้ เพื่อสรุปรายได้แต่ละวันStructuredเป็นตัวเลขในตาราง
ข้อมูลเจ้าของเหตุผล
ข้อมูลผู้ให้บริการมือถือที่เป็น Partner (บอก Location ลูกค้า)Second Partyเป็นข้อมูลของ Partner
ข้อมูลที่ลูกค้าสมัคร Member กับร้านในเครือFirst Partyร้านเก็บเองจากลูกค้าโดยตรง
Transactions ที่ลูกค้าซื้อสินค้าจากร้านในเครือFirst Partyเกิดในระบบของร้านเอง

จุดที่มักพลาด

  • เห็นตัวเลขแล้วตอบ Numerical ทันที — คะแนนความพึงพอใจ 1–5 ในสไลด์จัดเป็น Ordinal (Categorical) เพราะเป็นระดับที่มีลำดับ
  • สลับ 20% กับ 80% — ข้อมูลส่วนใหญ่ขององค์กร (80%) เป็น Unstructured
  • คิดว่า 3rd Party คุณภาพดีที่สุดเพราะข้อมูลเยอะ — 3rd Party มี Reach สูงสุด แต่ Quality ต่ำสุด
  • สับสน 2nd กับ 3rd Party — คำว่า Partner คือ 2nd Party
  • คิดว่าเก็บข้อมูลส่วนบุคคลจากแหล่งอื่นได้ถ้าเปิดเผยอยู่แล้ว — ต้องเก็บโดยตรงจากเจ้าของข้อมูลและได้รับ Consent

สรุปก่อนสอบ

  • แบ่งข้อมูลได้ 3 แบบ: ตามโครงสร้าง · ตามเจ้าของ · ตามสถิติ
  • Structured: แถว/คอลัมน์ได้, ~20%, ใช้พื้นที่น้อย, จัดการง่าย · Unstructured: รูป เสียง วิดีโอ, ~80%, ใช้พื้นที่มาก, จัดการยาก
  • 1st Party (เก็บเอง, Quality สูงสุด) · 2nd Party (ของ Partner) · 3rd Party (Reach สูงสุด, Quality ต่ำสุด)
  • Numerical: Discrete (จำนวนลูกค้า) / Continuous (ยอดขาย) · Categorical: Nominal (เพศ) / Ordinal (คะแนนความพึงพอใจ)
  • ER = Entity Relationship · Customer ID เชื่อมตารางและช่วยลดการเปิดเผยข้อมูลส่วนบุคคล
  • ใช้ข้อมูล: Dashboard ติดตาม KPI · วิเคราะห์สถานะธุรกิจ · AI/ML ทำนาย Churn, CLTV
  • PDPA 5 ข้อ: Consent · ไม่เกินจำเป็น · บอกวัตถุประสงค์ · แจ้งเมื่อเปลี่ยนวัตถุประสงค์ · เก็บจากเจ้าของโดยตรง
