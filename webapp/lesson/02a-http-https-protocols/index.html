HTTP/HTTPS และโปรโตคอลที่เกี่ยวข้อง

หมายเหตุจากเอกสาร

Scope 2026A ข้อ 2 คือ "HTTP/HTTPS and related protocols" สไลด์ HTTP for Developer ครอบคลุม HTTP message, status code, port 80/443, TCP three-way handshake, DNS และ HTTPS เพียงประโยคเดียว บทนี้เป็น เนื้อหาเสริม ที่ขยายส่วน "HTTPS" และ "related protocols" ให้ครบ ส่วนที่มาจากสไลด์กำกับไว้ว่า (สไลด์)

นึกภาพก่อน

ส่งจดหมายหนึ่งฉบับต้องมีหลายคนช่วยกัน: สมุดโทรศัพท์บอกที่อยู่ (DNS), บุรุษไปรษณีย์ส่งให้ถึงบ้าน (IP), ระบบลงทะเบียนรับรองว่าครบทุกหน้า (TCP), ซองกันน้ำที่เปิดอ่านระหว่างทางไม่ได้ (TLS) และภาษาที่เขียนในจดหมาย (HTTP) แต่ละชั้นทำงานของตัวเอง และชั้นบนพึ่งชั้นล่าง

สไลด์: HTTP เป็น application layer protocol ที่ ส่งผ่าน TCP และเป็น text-based client-server protocol

TCP เทียบ UDP

TCPUDP
การเชื่อมต่อต้องเปิด connection ก่อน (three-way handshake: SYN → SYN-ACK → ACK ตามสไลด์)ไม่ต้องเปิด connection
ความน่าเชื่อถือรับประกันว่าข้อมูล ครบและเรียงลำดับ ส่งซ้ำเมื่อหายไม่รับประกัน อาจหายหรือสลับลำดับ
ความเร็วช้ากว่า (overhead มาก)เร็วกว่า
ใช้กับเว็บ (HTTP/1.1, HTTP/2), อีเมล, ไฟล์วิดีโอสด, เกมออนไลน์, DNS query ส่วนใหญ่, HTTP/3 (ผ่าน QUIC)

DNS

แปลง ชื่อโดเมน → IP address (สไลด์: www.example.com → 3.165.82.61) ไล่ถาม root → TLD (.com) → authoritative server และ browser กับระบบปฏิบัติการ cache ผลไว้

HTTPS

HTTPS = HTTP + TLS — สไลด์: "HTTPS is a secure way to send data between a web server and a web browser" และใช้ port 443 (HTTP ใช้ 80)

TLS ให้อะไรความหมายกันอะไร
Encryption (การเข้ารหัส)คนกลางดักได้แต่อ่านไม่ออกขโมยรหัสผ่านใน Wi-Fi สาธารณะ
Authentication (ยืนยันตัวตน)certificate ที่ CA เซ็นรับรองว่า server เป็นเจ้าของโดเมนจริงเว็บปลอมที่แอบอ้างชื่อ
Integrity (ความถูกต้องครบถ้วน)ข้อมูลถูกแก้ระหว่างทางจะตรวจพบการแทรกโฆษณาหรือโค้ดระหว่างทาง

ขั้นตอนโดยย่อ:

  1. DNS lookup ได้ IP
  2. TCP three-way handshake
  3. TLS handshake: server ส่ง certificate → browser ตรวจว่าเชื่อถือได้ → ตกลง session key ร่วมกัน
  4. ส่ง HTTP request / response ที่ เข้ารหัสด้วย session key
  • HTTPS เข้ารหัส ทั้ง header, body และ path แต่ ชื่อโดเมน และ IP ยังมองเห็นได้
  • รูปแม่กุญแจใน browser หมายถึงการเชื่อมต่อถูกเข้ารหัส ไม่ได้รับรองว่าเว็บนั้นซื่อสัตย์
  • หน้า HTTPS ที่โหลดไฟล์ผ่าน HTTP เรียกว่า mixed content browser จะบล็อกหรือเตือน

Stateless, cookie และ session

  • สไลด์: HTTP is stateless — ไม่มีความเชื่อมโยงระหว่างสอง request แม้อยู่บน connection เดียวกัน
  • สไลด์: "but not sessionless" — server ใช้ cookie สร้าง session ได้
    1. server ตอบ Set-Cookie: sessionId=abc123
    2. browser เก็บไว้และแนบ Cookie: sessionId=abc123 ไปกับทุก request ต่อไปยังโดเมนนั้น อัตโนมัติ
attribute ของ cookieความหมาย
HttpOnlyJavaScript อ่านไม่ได้
Secureส่งผ่าน HTTPS เท่านั้น
Max-Age / Expiresอายุของ cookie
SameSiteจำกัดการส่ง cookie ข้ามเว็บ

Cache

Cache-Control: max-age=3600 (ในตัวอย่าง response ของสไลด์) บอกว่า browser เก็บสำเนาไว้ใช้ได้ 3600 วินาที (1 ชั่วโมง) โดยไม่ต้องขอใหม่ เมื่อหมดอายุ browser อาจถามว่าเปลี่ยนไหม ถ้าไม่เปลี่ยน server ตอบ 304 Not Modified โดยไม่ส่ง body ซ้ำ

เวอร์ชันของ HTTP

เวอร์ชันจุดเด่นTransport
HTTP/1.1ข้อความ (text), reuse connection ได้ (keep-alive) แต่ส่งทีละ request ต่อ connectionTCP
HTTP/2binary, multiplexing (หลาย request พร้อมกันใน connection เดียว), บีบอัด headerTCP
HTTP/3ใช้ QUIC แก้ปัญหา packet หนึ่งหายแล้วทุก request ต้องรอ เชื่อมต่อเร็วกว่าUDP

ความหมายของ method, status code และ header เหมือนกันทุกเวอร์ชัน ต่างกันที่วิธีส่ง

WebSocket

HTTP เป็นแบบ client ถาม server ตอบ server เริ่มส่งเองไม่ได้ WebSocket เปิด connection ค้างไว้แล้วส่งได้ สองทางตลอดเวลา (full-duplex) เหมาะกับแชต, การแจ้งเตือนสด, เกม เริ่มจาก HTTP request ที่ขอ Upgrade แล้วเปลี่ยน URL เป็น ws:// หรือ wss:// (แบบเข้ารหัส)

จุดที่มักพลาด

  • คิดว่า HTTPS เป็นโปรโตคอลใหม่แยกจาก HTTP — คือ HTTP ที่วิ่งบน TLS ข้อความยังเหมือนเดิม
  • สลับ port 80 กับ 443
  • คิดว่า TLS ซ่อนชื่อโดเมน — ชื่อโดเมนและ IP ยังมองเห็นได้
  • คิดว่า POST เป็น idempotent — ส่งซ้ำจะสร้างข้อมูลซ้ำ
  • คิดว่า HTTP/3 ใช้ TCP — ใช้ QUIC บน UDP
  • คิดว่า stateless แปลว่าทำ login ไม่ได้ — ใช้ cookie หรือ token ทำ session ได้
  • คิดว่ารูปแม่กุญแจแปลว่าเว็บปลอดภัยไว้ใจได้ — แปลว่าการเชื่อมต่อถูกเข้ารหัสเท่านั้น

สรุปก่อนสอบ

  • HTTP: application layer, text-based, client-server, ส่งผ่าน TCP · port 80 · HTTPS = HTTP + TLS · port 443
  • TLS ให้ 3 อย่าง: encryption · authentication (certificate จาก CA) · integrity
  • ลำดับ: DNS → TCP handshake (SYN, SYN-ACK, ACK) → TLS handshake → HTTP request/response
  • TCP: มี connection, ครบและเรียงลำดับ · UDP: ไม่มี connection, เร็ว, ไม่รับประกัน
  • DNS: ชื่อโดเมน → IP (root → TLD → authoritative) · port 53
  • Safe: GET, HEAD, OPTIONS · Idempotent: GET, PUT, DELETE (+HEAD, OPTIONS) · POST ไม่ใช่ทั้งสองอย่าง
  • Stateless แต่ไม่ sessionless: Set-Cookie → browser แนบ Cookie อัตโนมัติ · HttpOnly / Secure
  • Cache-Control: max-age=3600 = cache 1 ชั่วโมง · 304 Not Modified
  • HTTP/1.1 text · HTTP/2 binary + multiplexing · HTTP/3 QUIC บน UDP
  • WebSocket: connection ค้าง ส่งสองทาง (ws://, wss://)
