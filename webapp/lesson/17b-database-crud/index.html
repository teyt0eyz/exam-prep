ฐานข้อมูล SQL กับ CRUD: จาก route ถึงตาราง

หมายเหตุจากเอกสาร

บทเรียนนี้เป็น เนื้อหาเสริม: ไม่มีเอกสารใน docs/WEB/ เนื้อหาเขียนจากความรู้ทั่วไปเพื่อให้ครอบคลุมส่วนเก็บข้อมูลของ backend (ตัวอย่างใช้ SQL เป็นหลัก ถ้าอาจารย์ใช้ MongoDB หรือ ORM ตัวอื่น แนวคิด CRUD เหมือนกันแต่คำสั่งต่างกัน) รายละเอียดและตัวอย่างที่อาจารย์ใช้ในห้องอาจต่างจากนี้ ถ้ามีสไลด์หรือโค้ดจากห้องเรียน ให้ยึดตามนั้น

นึกภาพก่อน

บท Express เก็บ users ไว้ใน array ของโปรแกรม พอ restart server ข้อมูลหายหมด และถ้าเปิด server สองเครื่อง แต่ละเครื่องก็มี array ของตัวเอง ฐานข้อมูล คือที่เก็บข้อมูลถาวรนอกโปรแกรม ที่หลาย request และหลาย server ใช้ร่วมกันได้

SELECT posts.title, users.name

JOIN users ON posts.user_id = users.id;
ส่วนทำอะไร
SELECT คอลัมน์เลือกคอลัมน์ (* = ทุกคอลัมน์)
WHEREกรองแถว
ORDER BY ... ASC/DESCเรียงลำดับ
LIMIT nจำกัดจำนวนแถว
JOIN ... ONรวมแถวจากสองตารางที่ key ตรงกัน

UPDATE และ DELETE ที่ไม่มี WHERE จะมีผลกับทุกแถว

ต่อ Express กับฐานข้อมูล

การคุยกับฐานข้อมูลเป็นงาน asynchronous handler จึงเป็น async และใช้ await

js
app.get('/users/:id', async (req, res, next) => {
  try {
    const [rows] = await db.query('SELECT * FROM users WHERE id = ?', [req.params.id]);
    if (rows.length === 0) return res.status(404).json({ message: 'User not found' });
    res.json(rows[0]);
  } catch (err) {
    next(err);
  }
});

app.post('/users', async (req, res, next) => {
  try {
    const { name, email } = req.body;
    const [result] = await db.query('INSERT INTO users (name, email) VALUES (?, ?)', [name, email]);
    res.status(201).json({ id: result.insertId, name, email });
  } catch (err) {
    next(err);
  }
});

SQL injection

js
// อันตราย: เอาข้อความจากผู้ใช้มาต่อเป็นคำสั่ง
db.query("SELECT * FROM users WHERE name = '" + req.query.name + "'");
// ถ้า name คือ  ' OR '1'='1  เงื่อนไขจะเป็นจริงทุกแถว

// ปลอดภัย: parameterized query
db.query('SELECT * FROM users WHERE name = ?', [req.query.name]);

เครื่องหมาย ? (placeholder) ทำให้ฐานข้อมูลมองค่าจากผู้ใช้เป็น ข้อมูล ไม่ใช่ คำสั่ง

รายละเอียดของ MongoDB และ Mongoose อยู่ในบทถัดไป

ORM ให้เขียนเป็น method ของ JavaScript แทน SQL ตรง ๆ และกัน SQL injection ให้ในตัว แต่เบื้องหลังยังเป็น CRUD สี่อย่างเดิม

จุดที่มักพลาด

  • ลืม WHERE ใน UPDATE หรือ DELETE
  • ต่อ string จากผู้ใช้เข้าไปในคำสั่ง SQL
  • ลืม await ตอนเรียกฐานข้อมูล แล้วได้ Promise แทนข้อมูล
  • สลับ primary key กับ foreign key
  • ตอบ 200 เมื่อสร้างสำเร็จ (ควร 201) หรือตอบ 200 พร้อม array ว่างเมื่อหา id ไม่เจอ (ควร 404)
  • เก็บข้อมูลใน array ของโปรแกรมแล้วคาดว่าจะอยู่หลัง restart
  • เขียนรหัสผ่านของฐานข้อมูลไว้ในโค้ด แทนที่จะใช้ .env

สรุปก่อนสอบ

  • ฐานข้อมูลเก็บข้อมูลถาวรนอกโปรแกรม · array ในหน่วยความจำหายเมื่อ restart
  • SQL: ตาราง, schema ตายตัว, JOIN (MySQL, PostgreSQL) · NoSQL: document คล้าย JSON, ยืดหยุ่น (MongoDB)
  • Primary key ระบุแถวไม่ซ้ำ · Foreign key ชี้ไป primary key ของอีกตาราง
  • CRUD ↔ HTTP ↔ SQL: Create/POST/INSERT · Read/GET/SELECT · Update/PUT,PATCH/UPDATE · Delete/DELETE/DELETE
  • WHERE กรอง · ORDER BY เรียง · LIMIT จำกัดจำนวน · JOIN ... ON รวมตาราง
  • UPDATE / DELETE ไม่มี WHERE = ทุกแถว
  • งานฐานข้อมูลเป็น async → handler ใช้ async/await กับ try/catch
  • กัน SQL injection ด้วย parameterized query (?) หรือ ORM
