Full-stack: ตามรอย request จากปุ่มถึงฐานข้อมูลและกลับ

หมายเหตุจากเอกสาร

บทเรียนนี้เป็น เนื้อหาเสริม: ไม่มีเอกสารใน docs/WEB/ เนื้อหาเขียนจากความรู้ทั่วไปเพื่อให้ครอบคลุมภาพรวมที่เชื่อมทุกบทของ frontend และ backend เข้าด้วยกัน รายละเอียดและตัวอย่างที่อาจารย์ใช้ในห้องอาจต่างจากนี้ ถ้ามีสไลด์หรือโค้ดจากห้องเรียน ให้ยึดตามนั้น

นึกภาพก่อน

ลูกค้าสั่งอาหารกับพนักงาน พนักงานเขียนใบสั่งส่งเข้าครัว ครัวหยิบของจากตู้เย็น ทำเสร็จส่งกลับ พนักงานยกมาเสิร์ฟ หน้าเว็บคือพนักงาน API คือช่องส่งใบสั่ง server คือครัว และฐานข้อมูลคือตู้เย็น ถ้าอาหารไม่มา ต้องไล่ดูว่าใบสั่งค้างอยู่ที่ช่วงไหน

สามชั้นของเว็บแอป

ชั้นทำอะไรเทคโนโลยีในวิชานี้รันที่
Frontendแสดงผลและรับการกระทำของผู้ใช้HTML, CSS, JavaScript, React, Next.jsbrowser
Backendตรวจสิทธิ์ ตรวจข้อมูล ทำงานตาม business logicNode.js, Expressserver
Databaseเก็บข้อมูลถาวรSQL หรือ NoSQLserver

สิ่งที่เชื่อมแต่ละชั้น: frontend ↔ backend คุยกันด้วย HTTP + JSON ส่วน backend ↔ database คุยกันด้วย query

ตามรอย: เพิ่ม user หนึ่งคน

ขั้นที่ไหนเกิดอะไรบทที่เกี่ยวข้อง
1Reactผู้ใช้พิมพ์ชื่อ → onChange → setNameฟอร์มและ state
2Reactกดส่ง → onSubmit → e.preventDefault()ฟอร์มและ state
3browserfetch(url, { method: 'POST', headers, body: JSON.stringify(...) })Async และ fetch
4browserเพราะคนละ origin จึงส่ง preflight OPTIONS ก่อนCORS
5เครือข่ายHTTP request: POST /users, header Content-Type และ Authorization, body เป็น JSONHTTP message
6Expresscors() → express.json() → requireAuth → validateUserMiddleware
7Expresshandler เรียก await db.query('INSERT ...')ฐานข้อมูล
8Databaseเพิ่มแถวใหม่ คืน idฐานข้อมูล
9Expressres.status(201).json({ id, name })REST และ status code
10browserres.ok เป็น true → await res.json()Async และ fetch
11ReactsetUsers([...users, created]) → render ใหม่State แบบ immutable

ข้อมูลเปลี่ยนรูปตลอดทาง: object ใน JavaScript → ข้อความ JSON → object ใน req.body → แถวในตาราง → object → ข้อความ JSON → object → state

ใครตรวจอะไร

ตรวจFrontendBackend
ช่องว่าง รูปแบบอีเมลตรวจเพื่อ ความสะดวกของผู้ใช้ (เตือนทันที)ต้องตรวจซ้ำเสมอ
สิทธิ์การเข้าถึงซ่อนปุ่มหรือหน้าเพื่อ UXตัดสินจริง ด้วย token
ข้อมูลซ้ำ (เช่น email)ทำไม่ได้ตรวจกับฐานข้อมูล → 409

หลัก: frontend แก้ไขได้โดยผู้ใช้เสมอ (เปิด DevTools หรือยิง API ตรง ๆ ด้วย Bruno) ความปลอดภัยจึงต้องอยู่ที่ backend

เมื่อไม่ทำงาน: ไล่จากอาการ

อาการสาเหตุที่พบบ่อยดูที่ไหน
Console ขึ้น CORS errorbackend ไม่ได้ใช้ cors() หรือ origin ไม่ตรงConsole ของ browser
Failed to fetch / ERR_CONNECTION_REFUSEDserver ไม่ได้รัน หรือ port / URL ผิดTerminal ของ backend
404path หรือ method ไม่ตรงกับ routeแท็บ Network
400body ไม่ครบ หรือชื่อ field ไม่ตรงกับที่ backend รอแท็บ Network → Payload
req.body เป็น undefinedไม่มี express.json() หรือลืม header Content-Typeโค้ด backend
401ไม่ได้แนบ token หรือ token หมดอายุแท็บ Network → Headers
500โค้ด backend หรือ query พังTerminal ของ backend
ได้ 200 แต่จอไม่เปลี่ยนไม่ได้ setState หรือแก้ state ของเดิมตรง ๆโค้ด React
ได้ Promise { <pending> }ลืม awaitโค้ดที่เรียก
request ยิงรัวไม่หยุดuseEffect ไม่มี dependency arrayโค้ด React

วิธีแบ่งครึ่งปัญหา: ยิง API ด้วย Bruno ก่อน ถ้า Bruno ได้ผลถูก ปัญหาอยู่ฝั่ง frontend ถ้า Bruno ก็ผิด ปัญหาอยู่ฝั่ง backend

URL ของ API และ environment

frontend ไม่ควรเขียน http://localhost:3000 ตายตัว เพราะตอนขึ้นระบบจริง URL เปลี่ยน

js
// Vite
const API = import.meta.env.VITE_API_URL;
// Next.js (ตัวแปรที่ส่งไป browser ต้องขึ้นต้นด้วย NEXT_PUBLIC_)
const API2 = process.env.NEXT_PUBLIC_API_URL;

fetch(`${API}/users`);

ตัวแปร environment ฝั่ง frontend ไม่ใช่ความลับ เพราะถูกฝังในไฟล์ JavaScript ที่ส่งไป browser ความลับ (รหัสฐานข้อมูล, JWT secret) ต้องอยู่ฝั่ง backend เท่านั้น

ตัวอย่างไล่ทีละขั้น

อาการ: กดปุ่ม "เพิ่ม" ในหน้า React แล้วไม่มีอะไรเกิดขึ้น

  1. เปิด Console: ไม่มี CORS error → ผ่านด่าน CORS
  2. เปิด Network: เห็น POST /users ได้ status 400
  3. ดู Payload: ส่ง {"username":"Ann"}
  4. ดู response: {"message":"name is required"}
  5. สรุป: frontend ใช้ชื่อ field username แต่ backend รอ name → แก้ให้ตรงกัน
  6. ยืนยันด้วย Bruno: ส่ง {"name":"Ann"} ได้ 201 → backend ถูกต้อง ปัญหาอยู่ที่ frontend จริง

จุดที่มักพลาด

  • ตรวจข้อมูลและสิทธิ์เฉพาะที่ frontend
  • เดาสาเหตุโดยไม่เปิดแท็บ Network ดู status และ payload
  • ชื่อ field ของ frontend กับ backend ไม่ตรงกัน
  • อัปเดตจอจากค่าที่ผู้ใช้พิมพ์ แทนที่จะใช้ค่าที่ server ตอบ (ซึ่งมี id จริง)
  • ใส่ความลับในตัวแปร environment ของ frontend
  • คิดว่า CORS error แปลว่า backend พัง — request อาจถึง backend แล้ว แต่ browser ไม่ยอมให้ JavaScript อ่านคำตอบ

สรุปก่อนสอบ

  • สามชั้น: Frontend (browser) ↔ HTTP + JSON ↔ Backend (server) ↔ query ↔ Database
  • เส้นทาง POST: ฟอร์ม → fetch → (preflight) → middleware → handler → INSERT → 201 → res.json() → setState
  • ข้อมูลเปลี่ยนรูป: object → JSON string → req.body → แถวในตาราง → JSON → state
  • Frontend ตรวจเพื่อ UX · Backend ต้องตรวจซ้ำและตัดสินสิทธิ์เสมอ
  • ไล่ปัญหา: Console (CORS, JS error) · Network (status, payload) · Terminal ของ backend (500) · Bruno แบ่งครึ่งปัญหา
  • CORS error → แก้ที่ backend · req.body undefined → express.json() และ Content-Type · 401 → token
  • ตัวแปร environment ของ frontend ไม่ใช่ความลับ
  • Next.js รวม frontend กับ API ไว้ origin เดียว จึงไม่ต้องตั้ง CORS
